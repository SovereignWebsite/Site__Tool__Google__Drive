Google Cloud set-up

These steps are the owner's (Dinis's) to do in Google Cloud. Until they are done, the Connect page says it is not set up. Nothing here is a secret: the browser sign-in flow has no client secret.

1. One project, two APIs

The Gmail tool's client is an Internal one in RiskMandate's project, so outside people cannot sign in with it. This tool is for an outside team, so it needs its own External client. In a project for it, enable Google Drive API and Google Picker API.

2. OAuth consent screen

  • App name: Sovereign Website Drive
  • Authorised domain: sovereignweb.site (an External app's branding check may need the domain verified in Google Search Console; the Gmail tool's Internal client skipped this, so Dinis verifies it if Google asks)
  • Home page: https://drive.google.tool.sovereignweb.site/
  • Privacy policy: https://drive.google.tool.sovereignweb.site/app/privacy/
  • Scope to add: https://www.googleapis.com/auth/drive.file and nothing else
  • Publishing status: In production. In Testing, tokens last 7 days and only listed test users can sign in.

3. OAuth client (Web application)

  • Authorised JavaScript origins: https://drive.google.tool.sovereignweb.site
  • Authorised redirect URIs: https://drive.google.tool.sovereignweb.site/app/connect/. The sign-in is Google's OAuth token flow for web apps (a redirect that returns the token in the URL fragment). No Google script is loaded for sign-in.
  • Copy the client ID into site/app/config.js as clientId (public value).

4. Browser API key (for the Picker)

  • Application restriction: HTTP referrers, https://drive.google.tool.sovereignweb.site/*
  • API restriction: Google Picker API
  • Copy it into config.js as apiKey, and the project number as appId.

What the agent does next

Once the three public values are in config.js (an agent can commit them when Dinis gives them), the Connect and Browse pages work end to end. Until then they have not been tried against Google.
