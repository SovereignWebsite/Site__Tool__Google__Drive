Drive API

One ES module with no dependencies, served from this site. Any website can import it to sign people in with Google and use their Drive, from their own browser. There is no server of ours in the path and no telemetry. The Drive browser is built on it.

Versions

  • Pinned: https://drive.google.tool.sovereignweb.site/api/v0.3.0/drive.mjs. Never changes once released.
  • Latest: https://drive.google.tool.sovereignweb.site/api/latest/drive.mjs. Moves only on a release. Use it for demos only. A site with real users imports a pinned version with its hash: whoever can change what latest serves would otherwise get every importing site's token.
  • Hashes for every version: /api/versions.json. Changes: changelog.

Use it

You bring your own Google OAuth client id. In Google Cloud, add your site's origin and the redirect page below to a Web client. Google only returns tokens to origins registered on the client, so this is how each site stays its own. This site's client serves only this site.

<!-- optional: check the file against its hash (add crossorigin) -->
<link rel="modulepreload" crossorigin href="https://drive.google.tool.sovereignweb.site/api/v0.3.0/drive.mjs"
      integrity="sha384-FUM1AzFRHB3ozymPHEnxawG9OVXXd+Q5mq4E8IsNAxNflfdQ09P0EkYxpO3GXYc8">
<script type="module">
import { createDrive, SCOPES } from 'https://drive.google.tool.sovereignweb.site/api/v0.3.0/drive.mjs';
const drive = createDrive({ clientId: 'YOUR_CLIENT_ID.apps.googleusercontent.com', scope: SCOPES.file,
                            redirectUri: location.origin + '/connect/' });
await drive.handleRedirect();   // on the redirect page: stores the token, strips it from the URL
if (!(await drive.isSignedIn())) button.onclick = () => drive.signIn();   // call from a button press
else {
  const { files } = await drive.list();                  // or { parent: folderId }
  const hits = await drive.search('budget');
  const { bytes, type } = await drive.download(files[0].id);
  const made = await drive.createFolder('Backups');
  await drive.upload(new Blob(['hello']), { name: 'hello.txt', type: 'text/plain', parent: made.id });
}
</script>

A module import cannot carry an integrity attribute itself; the modulepreload link above makes the browser check the hash before the import uses the file.

Calls (the same in every version)

All calls return promises. Errors are DriveError with a status.
CallDoes
signIn(), handleRedirect(), isSignedIn(), signOut()Google's OAuth token flow for web apps, with a state check. Sign-out revokes the token.
list({parent, q, pageToken}), search(text), get(id)List folders and files (not trashed), search by name or content, read one file's details.
download(id, type?), exportFile(id, type), text(id)Content as bytes, or exported from Docs, Sheets and Slides (PDF, CSV, DOCX and so on).
upload(data, {name, type, parent}), createFolder(name, parent), move(id, parent), trash(id)Write. Trash goes to the Drive bin and never deletes for good. Upload is one request, for files up to a few MB.

Coming, as new versions: Sheets as a database (create a sheet, read and append rows as JSON with a header row as the schema), resumable upload, and backup and export helpers.

Scopes

SCOPES.file (drive.file) is the default and needs no restricted review, but sees only files your site creates or the person picks. SCOPES.readonly and SCOPES.full see the whole Drive and are restricted: Google's verification applies to a public client. The API supports all three and your site chooses. The cost and the recommendation are on the scopes page.

Using it safely

  • What the sealed token protects. The token is kept encrypted with a key the browser will not export, so it cannot be read from disk. It does not protect against script running on your own origin: any script there can use the stored key or ask for the token. Your page's Content-Security-Policy and the absence of cross-site scripting and third-party script are the real control.
  • token() is off. It throws unless you pass exposeToken: true, which only Google's own widgets (the Picker) need.
  • No wider token. The request never asks Google to add scopes you granted before, and a token that comes back with more access than you asked for is refused.
  • Pin and check. Import a pinned version with its hash. Use latest for demos only.
  • The sign-in return page. Load nothing from another site before handleRedirect() runs, and send Referrer-Policy: no-referrer (a <meta name="referrer" content="no-referrer"> works). The token comes back in the URL fragment, which Google's token flow for browsers uses; Google documents it, but the OAuth security guidance prefers a code flow, which we will move to when Google allows it without a secret in the browser.
  • Set exact hosts in your CSP. connect-src https://www.googleapis.com https://oauth2.googleapis.com, not *.googleapis.com or https:.
  • Downloaded files can be anything a stranger shared. Never render downloaded HTML or SVG on your own origin: offer a download, or show it in a sandboxed frame. Open webViewLink with rel="noopener noreferrer".
  • Not yet proven against real Google. Every version so far is tested against a mocked Google only. Treat the API as experimental until a release says otherwise.

How the token is kept

For its hour only, encrypted with a non-extractable key held in the browser's IndexedDB (memory if that is unavailable). It is sent only to Google's API hosts. Set your own page's connect-src to Google's API hosts and nothing else.

There is deliberately no broker mode (a pop-up on this site handing a token to another origin): any site could then ask for someone's Drive.
